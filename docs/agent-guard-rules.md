# エージェント運用のガードルール（実運用5か月の事故対策）

「AIエージェントは事故る」（borot 監修: からあげ、2026-06-14）と xangi を用いた
Claude Code + Discord 常時運用（約5か月・事故14件以上の実録）から得た教訓を、
ローカルLLM + Discord を併用する自前エージェントの運用に取り入れた際に
実際に効いていると評価したルール集です。

以下は `AGENTS.md` 等のエージェント行動規範にそのまま転記して使える形で書いています。

## 検索・対話のガードルール

- **過去参照シグナル = 検索コマンド**: 「前に」「以前」「あの時」「この間の」
  「前に動かしてるけど」等の語彙が出たら、修飾語として聞き流さず
  記録検索のトリガーとして扱い、検索してから答える
- **赤信号トリガー（出口検問）**: 自分の回答ドラフトに「一般的には」「相場感では」
  「だいたい」「おそらく」「未計測です」「記録が見当たらず」等を書こうとした瞬間は
  推測で埋めようとしているサイン。手を止めてローカル記録・資料を検索してから出力する
- **外部取得後の二段検索**: Web・フォーラム・論文等で外部情報を取得した後も、
  同じトピックでローカル記録を必ず引き直す（外部取得の成功体験が内部検索動機を
  上書きする = 最大の罠）
- **0件報告の義務**: 「探したけど無い」は、検索手段を全部消化して初めて
  口にしてよい結論。0件を黙って飲み込まない
- **turn-based宣言**: 「あとで確認します」「完了したら報告します」系の自走約束は、
  スケジューラ登録なしでは実行不可能（ターン終了と共に約束した主体が消える）。
  約束の前にスケジュール登録するか、ハンドオフ（「終わったら連絡して」）へ明示的に変える
- **出典のない回答をしない**: 調査結果・回答には、必ず「どの資料のどの部分か」
  （ファイル名・節・ページ等）を明記する。資料にない場合は「該当記録なし」と明示し、
  推定・一般論で補う場合は「資料外・推定」と区別して明記する

## 消し込み・同期のガードルール（複数環境運用向け）

- **複製ファイルの同期チェック**: AGENTS.md 等を複数のクローン／複数マシンに配布している場合、
  1箇所を更新したら**必ず全コピー先へ同期し、md5sum等で一致確認**してから報告する。
  上書きコピーの際は既存セクションを消していないか diff/grep で確認する
- **言動一致チェック**: 「〜しました」と報告する前に、その操作が実際に完了していることを
  実体確認する（ls/stat/cat/md5sum 等で対象を直接確認）。確認前の完了報告は禁止。
  特に「別フォルダ／別マシンへのコピー」「アーカイブ差し替え」は報告直後に再確認する
- **アーカイブ提出前の検証**: tar.gz 等を提出する前は同梱物を `tar -tzf` で検証する。
  同期漏れは「後で予測不能な問題」（設定消失・新旧混在）として発覚する

## 資料作成の品質チェック

- PDF・図解・資料を作ったら、生成後にレンダリング確認（pdftoppm 等でページ画像化して目視）
  を行い、①画像の破綻・はみ出し ②文字の読みにくさ・小さすぎ ③重なり を確認・修正してから
  報告する。「作ったからOK」で報告しない

## 運用方針（ガードの選定基準）

- 初発で被害小 → 教訓アーカイブに1行記録
- 再発 or 被害中 → 行動規範（AGENTS.md 等）へルール化し、該当スキルにも組み込む
- 3回以上再発 or 不可逆 → 機械ガード（hooks・プラグイン等）で強制する
- 不可逆系（外部送信・削除・push）は再発防止を最優先に設計する
